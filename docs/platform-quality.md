# Качество платформы — 5 сентября 2026

## Что изменено

- Курсы сохраняются и удаляются в интерфейсе после подтверждения сервера. Ошибка больше не переключает облачное хранилище в локальный режим и не маскируется под успех.
- Автор курса сохраняется при редактировании другим сотрудником. Параллельные сохранения разных курсов не вытесняют друг друга из состояния React.
- Сохранение существующего курса атомарно проверяет исходный `updated_at` в запросе к Supabase. При конфликте, удалении или потере доступа редактор не перезаписывает чужие изменения. Новые курсы создаются через `insert`, без разрешающего перезапись `upsert`. Версия из ответа сервера возвращается в редактор для следующего сохранения.
- При ошибке сохранения можно скачать JSON-черновик. Это копия содержимого курса со ссылками на вложения, не резервная копия самих файлов; автоматический импорт пока не предусмотрен.
- Автосохранение останавливается при ошибке и предлагает повторную попытку. Закрытие вкладки с несохранёнными изменениями вызывает предупреждение браузера.
- Очередь несинхронизированного прогресса хранится отдельно для каждого пользователя. Запись выполняется последовательно; при восстановлении сети и после повторного открытия страницы очередь отправляется снова. Ошибки синхронизации видны пользователю.
- Повторное открытие завершённого урока не сбрасывает его статус. Удалённые уроки и повторяющиеся записи не повышают прогресс выше 100%.
- Медленный ответ загрузки прогресса не стирает завершение, выполненное после начала запроса. При отказе загрузки восстанавливаются резервная копия и очередь отправки; записи другого пользователя и повреждённые записи отбрасываются.
- Состояние курсов пересоздаётся при смене аккаунта. При отказе облачной загрузки курсов и центра проверки не показываются локальные данные другого пользователя.
- Восстановление пароля обрабатывает событие Supabase `PASSWORD_RECOVERY` и открывает форму нового пароля.
- Вход по логину меняет метаданные только после успешной проверки пароля. Обычный запрос с неизвестным логином больше не сканирует весь каталог аккаунтов. Для старой базы без таблицы профилей оставлена совместимость.
- Перевод требует действующей сессии. Добавлены защитные HTTP-заголовки для production.
- Обновлены Vite и транзитивные зависимости с известными уязвимостями.
- Изменение группы проверяет форму запроса и не очищает состав перед добавлением новых связей. Удаляются только исключённые участники и курсы.
- Страницы загружаются отдельными JavaScript-пакетами. Критическая ошибка отображает экран восстановления; неизвестный маршрут — страницу «Не найдено».
- Добавлены единые состояния загрузки и ошибок, видимый фокус, переход к содержимому, уведомление об отсутствии сети, поддержка уменьшенной анимации. Общие модальные окна поддерживают Escape, удержание и возврат фокуса.
- В центре проверки работают фильтры статуса, обновление, сброс поиска; выбранная работа соответствует активному фильтру.
- Отчёты рассчитывают назначения и завершение на сервере, читают данные постранично и экспортируются в CSV. Демонстрационные результаты удалены.
- Экран ролей показывает фактические системные права. Старый редактор локальных шаблонов, не влиявших на доступ, удалён из интерфейса; сохранённые в браузере шаблоны не удалялись.
- CSV-выгрузки экранируют потенциальные формулы, включая пользовательские названия и имена.
- Сертификаты в профиле используют общий прогресс курсов. Ошибки сохранения профиля и восстановления пароля не оставляют кнопки заблокированными.
- Обычный `npm run dev` обслуживает локальные API; необходимые серверные секреты читаются только в серверной части.
- Удалены 830 строк неиспользуемых демонстрационных экранов из App.tsx. Добавлены регрессионные тесты и CI.
- `npm run check` проверяет линтер, типы серверных обработчиков и тестов, регрессионные тесты и production-сборку. Раньше TypeScript-сборка не охватывала все серверные файлы.

## Границы проверки

Локальный результат: 50 тестов в 8 файлах, ESLint, TypeScript и production-сборка проходят. `npm audit` сообщает 0 известных уязвимостей. Сборка сохраняет предупреждение о размере отдельного пакета emoji-picker (~589 kB); он загружается при открытии выбора эмодзи, а не вместе с каждой страницей.

Регрессионные тесты проверяют логику на изолированных данных. Они не доказывают корректность настроек рабочего проекта Supabase, почтового сервиса, Vercel и TURN.

Во время проверки локальные административные API возвращали 503: серверная конфигурация Supabase отсутствует. Необходимо указать `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` в `.env.local` для локальной работы и в серверных переменных Vercel для production. Service-role ключ нельзя добавлять в переменные `VITE_*`.

Встроенный браузер отключился во время работы. Полный визуальный проход по desktop/mobile и тёмной теме после этих изменений не выполнен. Нужна проверка на 390, 570, 820 и 1440 px, включая длинные названия, пустые списки и сообщения об ошибках.

## Что ещё необходимо для полной готовности к эксплуатации

1. **Изолированный стенд и проверка доступа.** Проверить миграции 001–015, RLS и Storage отдельными аккаунтами ученика, наставника и администратора. Ученик не должен получать неназначенный курс или чужие ответы по прямому запросу. В этом проходе схема рабочей базы не менялась.
2. **Транзакции групп.** Состав группы теперь не очищается заранее, но несколько запросов ещё не являются одной транзакцией. Перенести изменение состава и синхронизацию назначений в проверенную PostgreSQL-функцию, затем испытать конкурентное изменение одной группы и откат при отказе.
3. **Конкурентные сценарии на стенде.** Проверка версии курса добавлена и покрыта тестами запросов, конфликта и повторного сохранения. Необходимо испытать её с реальными RLS/триггерами и двумя устройствами. Защита действует для обновлённого клиента: старый клиент или прямой API-запрос без проверки версии требует отдельного серверного ограничения. Проверить синхронизацию прогресса между устройствами: локальная очередь не заменяет серверное разрешение конфликтов.
4. **Эксплуатационная безопасность.** Настроить ограничения частоты входа и перевода на сервере/шлюзе, бюджет DeepL, почтовую доставку, резервное копирование и восстановление БД. Проверить правила хранения персональных данных. Эти настройки не заменяются frontend-кодом.
5. **Видеосвязь.** Испытать TURN между разными сетями, переподключение, демонстрацию экрана и комнаты с несколькими участниками. Определить требования к защищённым приглашениям и сроку жизни ссылок; сейчас вход гостя по ссылке — действующая модель продукта.
6. **Масштабирование.** В отчётах есть постраничное чтение; списки пользователей и другие клиентские выборки ещё требуют полной серверной пагинации и нагрузочного теста. Не обещать работу на десятках тысяч аккаунтов без этих измерений.
7. **Полный пользовательский проход.** Проверить регистрацию, письмо восстановления, сохранение курса, назначение группы, вход ученика, все типы заданий, вложения, ответ преподавателя и возврат в редактор конкретного урока. Внешние отправки и реальные удаления в ходе этого прохода не выполнялись.

Пользовательские роли, официальный выпуск проверяемых сертификатов и личный словарь требуют отдельной модели данных. Экран ролей и переводчик прямо сообщают об этих ограничениях; они не выдают прототип за действующий механизм.
